# 04 · 决策引擎

> 输入完整局面，输出每张可打牌的打分。
> 工作量约 20%，但开源可复用度最高。

## 输出格式

引擎对当前局面，对**自己手牌中每张可打的牌**给出：

```
{
  tile: "5筒",
  attack_score: 0.62,        # 进攻分 0-1
  defense_score: 0.81,       # 防守分 0-1（高=安全）
  combined_score: 0.71,      # 加权综合
  details: {
    shanten_after: 1,        # 打这张后向听数
    win_probability: 0.18,   # 蒙特卡洛胡牌概率
    expected_fan: 2.3,       # 期望番数
    danger_per_seat: {       # 对每家的危险度
      left: 0.05,
      across: 0.32,
      right: 0.12
    }
  }
}
```

UI 展示推荐 `combined_score` 最高的，悬停看 `details`。

## 三个子系统

### 4.1 向听数（shanten）

**复用方案**：fork `python-mahjong`（npm 上的 `mahjong` 也可以，但 Python 生态优先）。

要改的：

- **胡牌型判定**（核心改造）
  - 转转麻将三色（筒索万）齐全，序数牌 1-9 各 4 张
  - **无字牌、无赖子**：标准序数牌枚举
  - **无吃牌**：副露区只有碰/杠，shanten 计算时禁用"通过吃形成顺子"的搜索路径
  - 乱将：任意对子可做将
  - 支持特殊胡牌型：清一色、碰碰胡、七巧对、将将胡、全求人
  
- **听牌枚举**：返回所有听牌组合

- **保留**：基础的"几面子几搭子"逻辑、跑得通

预计代码改动 500-1000 行，主要在和牌判定函数。

详细规则见 [06-zhuanzhuan-rules.md](06-zhuanzhuan-rules.md)。

### 4.2 进攻评分：蒙特卡洛

**思路**：对每张可打牌，假装打出去，模拟剩余局面 N 次，统计胡牌结果。

```
对每张可打牌 t:
    模拟 1000 次:
        基于状态机的剩余牌山随机发牌
        模拟自己摸打 X 步（X=平均还有几手）
        其他家用简化策略（随机打或最大向听数下降）
        记录是否胡、胡的番数
    win_prob[t] = 胡的次数 / 1000
    expected_fan[t] = 胡时的平均番数
    attack_score[t] = f(win_prob, expected_fan, shanten_after)
```

**性能取舍**：1000 次模拟是起点。如果性能预算（80ms）跑不完，降到 500 或 200。模拟次数低噪声大，但比不算强。

**对手简化策略**：MVP-2 阶段对手用"最大向听数下降"启发式即可，不递归调用引擎（会无限循环）。

### 4.3 防守评分

完全用规则，不需要训模型。

#### 现物

某家自己打过的牌，再打一遍 100% 安全（那家不可能胡自己打过的牌）。

```
for tile in 自己可打牌:
    for seat in [left, across, right]:
        if tile in 该家弃牌区:
            danger[seat][tile] = 0
```

#### 筋

经典麻将概念。如果别人打过 4，那 1 和 7 相对安全（破坏了 4 的两面听结构）。

转转麻将只有筒条，逻辑直接套用日麻防守：

- 打过 4 → 1、7 是筋
- 打过 5 → 2、8 是筋
- 打过 6 → 3、9 是筋

筋不是绝对安全，是"相对安全"。

#### 壁

某张牌的 4 张已经全部可见（弃牌+碰杠+自己手里），它的相邻牌（±1、±2）有壁效应。

例：4 筒已经 4 张全可见，则 3 筒、5 筒不会被人用来搭 4 筒的两面听，相对安全。

#### 综合

```
defense_score[t] = min(对每家的安全度)
对每家的安全度 = 1 - 危险度
危险度 = w1 * 是否现物的反指标
       + w2 * 是否筋的反指标
       + w3 * 是否壁邻接的反指标
       + w4 * 该家是否疑似听牌
```

权重初始全部均匀，实战调。

### 4.4 综合融合

```
combined_score = attack_score * α + defense_score * β
```

α、β 动态：

- 自己已听 → α 大幅高，β 降低
- 自己分高、对手疑似听牌 → β 升高
- 对手都还远（向听数高）→ α 升高
- 最后几张时 → α 降低（搏胡 vs 防守反而要慎重）

初始权重和场景规则在 `src/engine/weights.py`，**版本化**，每次调参 commit 一次。

## 不做的事

- **不接 Mortal、NAGA 等日麻 AI**：规则不通，强行接 = 自己造一个不准的引擎
- **不训自己的神经网络**：成本不在预算内
- **不做对手手牌精确预测**：只做"疑似听牌"二分判定
- **不做"应该碰吗""应该杠吗"建议**（MVP-2 阶段）：碰杠由 Max 决定，引擎只在自己出牌时算

## 性能预算

每次推荐计算 ≤80ms。组成：

| 步骤 | 预算 |
|---|---|
| shanten 算各张 | 10ms |
| 蒙特卡洛 1000 次 | 50ms |
| 防守评分 | 5ms |
| 融合 + 排序 | 5ms |
| 余量 | 10ms |

蒙特卡洛是大头。性能不够时第一个调整。

## 可视化（强制）

UI 调试面板必须能查看：

- 每张可打牌的 attack/defense/combined 分项
- 蒙特卡洛模拟次数和当前耗时
- 当前权重 α、β
- 局势识别结果（"自己听牌"/"对手疑似听牌"等标志位）

引擎不是黑盒，所有打分都能追溯。

## 阶段性目标

- **Sprint 5**：shanten 正确，能识别听牌
- **Sprint 6**：进攻分能算，对比"什么都不算就打最右边"明显更优
- **Sprint 7**：防守分接入，能避开明显危险牌
- **Sprint 8**：在欢乐场实战，Max 主观觉得"差不多算个一般人"
