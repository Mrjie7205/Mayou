# 03 · 状态机

> 把"识别到的牌"翻译成"游戏中发生了什么"。
> 整个项目最容易写出隐蔽 bug 的地方。

## 它要维护什么（账本字段）

```
GameState
├── 自己手牌：13 或 14 张
├── 自己已打弃牌：list
├── 各家弃牌：dict[家位 → list]
├── 各家碰杠区：dict[家位 → list of 组]
│   每组：{type: peng|ming_gang|an_gang|jia_gang, tiles: [...]}
├── 当前轮到：家位
├── 最近一张打出：(家位, 牌)
├── 剩余牌山推算：dict[牌 → 张数]
├── 场风、圈风、庄家
├── 听牌信息：是否听、听什么、剩多少
└── 一局开始时间、当前回合数
```

## 家位约定

```
        对家 (across)
上家 (left)        下家 (right)
        自己 (self)
```

**坐位是固定的**，每局开始时根据 UI 确定。

## 事件类型

状态机响应这些事件：

| 事件 | 触发条件（识别层报告） | 状态机动作 |
|---|---|---|
| `draw` 摸牌 | 自己手牌从 13 变 14 / 别家从无变摸牌动画 | 剩余牌山 -1，轮到该家 |
| `discard` 打牌 | 弃牌区多一张 | 弃牌区添加，轮到下一家 |
| `peng` 碰 | 某家碰杠区多一组 3 张 + 上一张被打的牌消失 | 把那张牌从对应弃牌区移除（被碰走），轮到碰家 |
| `ming_gang` 明杠 | 某家碰杠区多一组 4 张 | 类似碰，但是 4 张 |
| `an_gang` 暗杠 | 某家碰杠区多一组 4 张背面（或带特殊标记） | 不影响剩余牌山可见性，轮到该家继续 |
| `jia_gang` 加杠 | 某家已有的碰组变成 4 张 | 碰组升级，轮到该家继续 |
| `hu` 胡 | UI 显示胡牌特效/结算页 | 标记一局结束 |
| `liu_ju` 流局 | UI 显示流局结算 | 标记一局结束 |

## 状态机的核心难点：识别变化 → 推断事件

识别层告诉状态机"这一帧画面长什么样"。状态机自己跟上一帧比对，**推断**发生了什么。

例子：

```
上一帧：对家弃牌区有 8 张牌，最后是 5 万
本一帧：对家弃牌区有 7 张牌，最后是 9 条
        下家碰杠区多了一组 [5万, 5万, 5万]
        当前轮到下家

推断：下家碰了对家的 5 万，那张 5 万从对家弃牌区被移走
事件：peng(actor=right, source=across, tile=5wan)
```

这种推断必须考虑顺序。建议处理优先级：

1. 先看碰杠区变化（碰/杠/胡）
2. 再看弃牌区变化（打牌）
3. 再看手牌区变化（摸牌）
4. 最后更新轮次

## 边角情况清单（先列着，遇到一个补一个）

不要试图一次性把这些都做对。MVP-1 先把最常见的 70% 处理掉，剩下的随用随补。

- 一炮多响（一张牌同时被多家胡）
- 抢杠胡（加杠时被胡）
- 暗杠不亮牌
- 海底捞月（最后一张牌胡）
- 流局
- 连庄
- 自摸 vs 点炮的区分
- 听牌后弃牌区有红色提示（如果云游戏 UI 显示）
- 别家长考时画面无变化（不要误判为状态异常）
- 跳过某家（罕见，但有些规则下因犯规可能跳过）
- 错过帧导致事件序列断裂（识别层没及时报告）

## UI 反向通道：手动修正

唯一允许的"反向通道"：UI → 状态机的手动修正。

场景：识别错了，Max 发现"实际上对家碰的是 3 条不是 4 条"，UI 上点修正，状态机更新。

实现要求：

- 每个状态字段都要支持外部 patch
- 修正后清除受影响的派生状态（剩余牌山等）重算
- 修正记录到事件日志，前缀 `[manual]`

## 调试与可视化

状态机必须支持：

- **事件流日志**：最近 N 条事件，UI 显示
- **状态快照导出**：随时把当前 GameState 序列化到 JSON
- **回放**：从事件流日志能完整重建任何中间状态（用于复现 bug）

如果一个 bug 不能从事件流复现，说明事件流不完整，先修这个。

## 验收标准

完整一局牌打完后：

- 事件序列与实际牌局一致率 ≥95%（MVP-1）
- 剩余牌山推算与真实剩余的差值 ≤2 张（误差主要来自暗杠和摸而未打的牌）
- 任何一帧状态可以序列化 + 反序列化无损
