# 02 · CV 流水线

> 采集层 + 识别层的设计细节。
> 这是 Mayou 工作量最大的部分（约 40%）。

## 截图：怎么稳定拿到画面

### 窗口定位

不直接截屏幕坐标（用户可能移动云游戏窗口）。流程：

1. 用 `pygetwindow` 按窗口标题找到云游戏窗口
2. 拿到窗口左上角坐标 + 大小
3. 用 `mss` 截这个窗口区域

如果窗口被遮挡或最小化，提示用户而不是返回错误数据。

### 区域配置

云游戏窗口里只有几块区域我们关心。每个平台一个 JSON 文件存在 `assets/configs/<platform>.json`：

```jsonc
{
  "platform": "<待定>",
  "window_title_pattern": "<匹配模式>",
  "regions": {
    "my_hand": {"x": 100, "y": 600, "w": 800, "h": 100},
    "discard_self": {...},
    "discard_left": {...},
    "discard_across": {...},
    "discard_right": {...},
    "meld_self": {...},
    "meld_left": {...},
    "meld_across": {...},
    "meld_right": {...},
    "last_played_highlight": {...},
    "turn_indicator": {...}
  },
  "tile_size": {"min_w": 30, "max_w": 50, "min_h": 40, "max_h": 60}
}
```

**这个文件由 `tools/region_picker.py` 生成**，不手写。

### 帧率

200ms 一帧，每秒 5 帧。理由：

- 麻将不是 FPS 游戏，5fps 够追
- 太高浪费 CPU
- 太低错过快速动画事件

### 动画防抖

牌被打出去/碰起来的瞬间是动画，识别会乱。机制：

- 连续 3 帧（即 600ms）识别结果一致才确认事件
- 帧间识别结果做 hash 对比，省去重复计算

## 识别：从图块到牌符

### 走模板匹配，不走神经网络

理由（也是 [CLAUDE.md](../CLAUDE.md) 里的强约束）：

| 方案 | 准确率 | 数据成本 | 计算成本 | 开发周期 |
|---|---|---|---|---|
| 模板匹配 | 99%+（固定 UI） | 每种牌 5-10 张 | 低 | 短 |
| 神经网络 | 99%+ | 每种牌数百张 + 标注 | 中（GPU） | 长 |

固定 UI 的前提下模板匹配上限够高，开发周期短，是合理选择。

### 模板库结构

```
assets/templates/
├── index.json                  # 总索引
├── tiles/
│   ├── tong_1/                 # 一筒
│   │   ├── 001.png
│   │   ├── 002.png
│   │   └── ...
│   ├── tong_2/
│   ├── ...
│   ├── tiao_1/                 # 一条（索）
│   ├── ...
│   ├── wan_1/                  # 一万
│   ├── ...
│   ├── wan_9/
│   └── back/                   # 背面（未亮的牌）
└── markers/
    ├── peng/                   # 碰标记
    ├── gang/                   # 杠标记
    ├── ting/                   # 听标记（如果云游戏 UI 有）
    └── turn_arrow/             # 当前出牌方向指示
```

转转麻将牌型：

- 筒 1-9（9 种）
- 索/条 1-9（9 种）
- 万 1-9（9 种）
- **没有字牌、没有红中、没有赖子、没有花牌**

加上背面和标记，模板库 28-30 类，每类 5-10 张样本，总数 140-300 张。

### 多尺度匹配

云游戏不同分辨率下牌的像素尺寸不同。匹配时在 ±15% 尺度范围内做金字塔搜索。

### 帧间差分（性能优化）

每帧把当前画面跟上一帧做差。只对**有变化的区域**重新识别，没变化的复用上次结果。

弃牌区一局牌打下来积累几十张，重复识别是浪费。

### 兜底：识别失败时怎么办

模板匹配返回置信度。置信度低于阈值（建议 0.8）时：

- 在 UI 调试区显示"低置信度"警告
- 不更新状态机（保留上次状态）
- 把这张图块存到 `assets/templates/_unrecognized/` 供 Max 后续补模板

**绝不在低置信度时强行更新状态机**，错的状态比缺的状态更糟。

## 调试可视化（强制）

CV 层必须支持"调试模式"开关。开启时：

- 每帧把截图 + 识别框 + 识别结果 + 置信度 渲染成一张图
- 保存到 `tools/debug_frames/YYYYMMDD/`
- UI 调试面板显示最近一帧

Max 报"识别错了"时，从这里直接看出是哪一步错。

## 测试数据集

`tests/cv_fixtures/`：

- 手工标注过的截图（图 + 标签 JSON）
- 每次改识别逻辑跑回归测试
- 准确率不达标禁止合并

## 常见坑预登记

| 现象 | 大概率原因 |
|---|---|
| 同一张牌时识别对时识别错 | 帧率太低，截到了动画中间 |
| 识别准确率突然全面下降 | 平台改版或显示器 DPI 改了 |
| 某几种牌一直识别错 | 模板样本数不够，需要补 |
| 弃牌区识别越来越慢 | 没启用帧间差分 |
| 万子和索子混淆 | 视觉相似（都是抽象图案），需要更多样本和更严格阈值 |
