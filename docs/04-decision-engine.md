# 04 · 决策引擎

> 输入完整局面，输出每张可打牌的打分。
> 工作量约 20%，但开源可复用度最高。

## 输出格式

引擎对当前局面，对**自己手牌中每张可打的牌**给出：

```
{
  tile: "5筒",
  attack_score: 0.62,        # 进攻分 0-1
  defense_score: 0.81,       # 防守分 0-1（高=安全）
  combined_score: 0.71,      # 加权综合
  details: {
    shanten_after: 1,        # 打这张后向听数
    win_probability: 0.18,   # 蒙特卡洛胡牌概率
    expected_fan: 2.3,       # 期望番数
    danger_per_seat: {       # 对每家的危险度
      left: 0.05,
      across: 0.32,
      right: 0.12
    }
  }
}
```

UI 展示推荐 `combined_score` 最高的，悬停看 `details`。

## 三个子系统

### 4.1 向听数（shanten）

**方案**：**从零自写字牌引擎**（见 [ADR-002](decisions/ADR-002-game-switch.md) 修正段）。

为什么不 fork 麻将库：株洲碰胡是**湖南字牌**（80 张大小写字牌），不是麻将。麻将开源库的牌张结构、面子定义、shanten 算法**全部不适用**。

要做的：

- **字牌胡牌型枚举**
  - 牌张：小写 10 + 大写 10 = 20 种字，每种 4 张，总 80 张
  - 基本组件：一对（将）/ 一坎（3 张）/ 一提（4 张）/ **一句话**（同字号连续 3 张；特殊：二七十、贰柒拾也算）/ **绞牌**（大对+小单 或 小对+大单）
  - 大小写不混（句话分支按字号分组）
  - 胡牌型 = N 个组件 + 1 对将，组件可以是坎/提/句话/绞牌的任意组合
  - 特殊胡型：天胡、地胡、五福、小七对、双龙（这些有起手或副露条件限制）

- **shanten 计算**：当前手牌（含副露）距离胡牌型的最少摸打步数

- **听牌枚举**：返回所有听牌组合及对应等待张

预计代码量 1000-2000 行，主要复杂度在：
- 一句话特殊连张「二七十/贰柒拾」分支
- 绞牌跨大小写组合识别
- 副露区强制动作（偎/提/跑）对 shanten 的影响
- 五福报警状态下听牌范围被限缩

详细规则见 [07-zhuzhou-pengHu-rules.md](07-zhuzhou-pengHu-rules.md)。

### 4.2 进攻评分：蒙特卡洛

**思路**：对每张可打牌，假装打出去，模拟剩余局面 N 次，统计胡牌结果。

```
对每张可打牌 t:
    模拟 1000 次:
        基于状态机的剩余牌山随机发牌
        模拟自己摸打 X 步（X=平均还有几手）
        其他家用简化策略（随机打或最大向听数下降）
        记录是否胡、胡的番数
    win_prob[t] = 胡的次数 / 1000
    expected_score[t] = 胡时的平均积分（按 docs/07 §6 计分表）
    attack_score[t] = f(win_prob, expected_score, shanten_after)
```

**性能取舍**：1000 次模拟是起点。如果性能预算（80ms）跑不完，降到 500 或 200。模拟次数低噪声大，但比不算强。

**对手简化策略**：MVP-2 阶段对手用"最大向听数下降"启发式即可，不递归调用引擎（会无限循环）。

### 4.3 防守评分

完全用规则，不需要训模型。

#### 现物

某家自己打过的牌，再打一遍 100% 安全（那家不可能胡自己打过的牌）。

```
for tile in 自己可打牌:
    for seat in [left, across, right]:
        if tile in 该家弃牌区:
            danger[seat][tile] = 0
```

#### 筋

字牌「一句话」≈ 麻将顺子，**所以筋概念适用**（撤回之前我误判的"不适用"）。

- 同字号内：打过 4 → 1、7 是筋；打过 5 → 2、8 是筋；打过 6 → 3、9 是筋
- 大小写不混筋
- **特殊**：二七十、贰柒拾 这两条特殊连张的筋逻辑 ⚠️ Sprint 7 实做时单独设计——「2、7、10」的筋是哪些？常规连张逻辑套不上

#### 壁

某字 4 张全可见（弃牌+副露+自己手里），其相邻字号搭子失效。

- 例：小 4 已 4 张全可见 → 小 3、小 5 不会被人用来搭句话两面听
- 大小写独立计算

#### 对手听张推测

字牌的副露强制动作（偎、提）会暴露大量信息：

- 某家偎过某张 → 必然手里有这张的一对升刻 → 听张范围收窄
- 某家提过某字 → 整提暗示
- 某家碰多了 → 五福报警风险，听张范围被规则限缩到「五福或跑胡」
- 弃牌历史读型：大小写偏向、红黑色偏向、字号集中度

具体启发式 Sprint 7 实做时设计，本节锁方向。

#### 综合

```
defense_score[t] = min(对每家的安全度)
对每家的安全度 = 1 - 危险度
危险度 = w1 * 是否现物的反指标
       + w2 * 是否筋的反指标
       + w3 * 是否壁邻接的反指标
       + w4 * 听张推测的命中度
       + w5 * 该家是否五福报警（高警戒）
```

权重初始全部均匀，实战调。

### 4.4 综合融合

```
combined_score = attack_score * α + defense_score * β
```

α、β 动态：

- 自己已听 → α 大幅高，β 降低
- 自己分高、对手疑似听牌 → β 升高
- 对手都还远（向听数高）→ α 升高
- 最后几张时 → α 降低（搏胡 vs 防守反而要慎重）

初始权重和场景规则在 `src/engine/weights.py`，**版本化**，每次调参 commit 一次。

## 不做的事

- **不接 Mortal、NAGA 等日麻 AI**：规则不通，强行接 = 自己造一个不准的引擎
- **不训自己的神经网络**：成本不在预算内
- **不做对手手牌精确预测**：只做"疑似听牌"二分判定
- **不做"应该碰吗""应该杠吗"建议**（MVP-2 阶段）：碰杠由 Max 决定，引擎只在自己出牌时算

## 性能预算

每次推荐计算 ≤80ms。组成：

| 步骤 | 预算 |
|---|---|
| shanten 算各张 | 10ms |
| 蒙特卡洛 1000 次 | 50ms |
| 防守评分 | 5ms |
| 融合 + 排序 | 5ms |
| 余量 | 10ms |

蒙特卡洛是大头。性能不够时第一个调整。

## 可视化（强制）

UI 调试面板必须能查看：

- 每张可打牌的 attack/defense/combined 分项
- 蒙特卡洛模拟次数和当前耗时
- 当前权重 α、β
- 局势识别结果（"自己听牌"/"对手疑似听牌"等标志位）

引擎不是黑盒，所有打分都能追溯。

## 阶段性目标

- **Sprint 5**：shanten 正确，能识别听牌
- **Sprint 6**：进攻分能算，对比"什么都不算就打最右边"明显更优
- **Sprint 7**：防守分接入，能避开明显危险牌
- **Sprint 8**：在欢乐场实战，Max 主观觉得"差不多算个一般人"
