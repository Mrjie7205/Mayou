# 07 · 株洲碰胡规则速查

> 引擎实现的唯一规则依据。
> ⚠️ **本文档为基于公开资料的初稿**。闲逸棋牌平台的具体规则细节需在 Sprint 0 实测时补全。所有标 ⚠️ 的字段视为待确认。
> 如果闲逸平台规则与本文档有出入，**以平台为准**，并在本文档对应位置加变体说明 + 修改 `assets/configs/<platform>.json` 的 `rule_variant`。

## 0. 一句话

株洲碰胡 = 「碰碰胡」作为唯一胡型的麻将玩法。**只能碰，不能吃；胡牌必须全是刻子/杠 + 1 对将**。

## 1. 牌张

**典型为 108 张** ⚠️ 待平台确认：
- 1-9 筒 × 4 = 36 张
- 1-9 索（条） × 4 = 36 张
- 1-9 万 × 4 = 36 张

**没有**：东南西北风、中发白、花牌、红中、赖子、任何字牌。

⚠️ 部分株洲碰胡变体只用单一花色（例如只用万 36 张）。开闲逸实机前必须确认是三色版本还是单色版本——这直接影响识别层（模板库容量 27 类 vs 9 类）和引擎层（清一色是否还作为加番）。

## 2. 起手

- 庄家 14 张，闲家各 13 张（典型麻将起手）⚠️ 平台确认
- 庄家先打第一张

## 3. 行牌动作

| 动作 | 株洲碰胡 | 说明 |
|---|---|---|
| 摸牌 | ✅ | |
| 打牌 | ✅ | |
| **吃** | ❌ | 无吃，与转转麻将相同 |
| 碰 | ✅ | 别家打的牌 + 自己手里 2 张 |
| 明杠 | ✅ | 碰过的牌再摸到第 4 张 |
| 暗杠 | ✅ | 手里 4 张相同 |
| 加杠 | ✅ | |
| 抢杠胡 | ✅ ⚠️ | 平台规则待确认；暗杠通常不可抢 |

⚠️ **"无吃 + 无顺子胡型"是株洲碰胡的核心特征**：

- 副露区永远只有碰、杠两种
- 引擎层的 shanten 计算**不需要枚举顺子**
- 大部分日麻 AI、国标 AI、转转麻将引擎都假设有顺子，**对株洲碰胡不能直接复用**

## 4. 胡牌牌型

### 4.1 唯一胡型

**胡牌时手中（含副露）必须全为刻子或杠 + 1 对将**：

- 4 副刻子（或杠）+ 1 对将 = 胡（共 14 张）
- 杠等价于刻子参与胡牌型
- 将 = 任意对子（乱将，任何一对都行）

**没有顺子型胡牌**——这是与转转麻将最大的差别。

### 4.2 特殊牌型（加番）⚠️ 平台变体

⚠️ 以下牌型在不同株洲碰胡变体中开关不一致，**全部待平台实测确认**。

| 牌型 | 说明 |
|---|---|
| 清一色 | 整副只有一色（三色版本下成立；单色版本下不成立） |
| 全求人 | 4 副副露 + 单钓将（除了听张全靠碰/杠形成） |
| 四暗刻 | 4 副刻子全部由自摸/起手形成（未碰出） |
| 七对子 | ⚠️ 株洲碰胡是否承认七对子作为胡型/加番待确认 |
| 大对子 / 碰碰胡 | 本玩法默认胡型，不作为加番项 |

## 5. 胡牌方式

- **自摸**：自己摸到胡牌张
- **点炮（捉炮）**：胡别家打出的牌
- **抢杠胡**：胡别家明杠/加杠的那张 ⚠️ 暗杠通常不可抢，平台确认
- **海底**：胡最后一张 ⚠️

## 6. 番数与计分概览

⚠️ **本节细节强烈建议平台实测后补全**。在引擎接入前，所有数字视为占位。

### 6.1 典型番数占位

- 平胡基础 1 番
- 自摸 +1 番 ⚠️
- 每个杠（明杠、暗杠、加杠）+1 番（即"一根筋"，可累加）⚠️
- 清一色、全求人、四暗刻 独立加番 ⚠️

引擎实现前，把这些番数提到 `assets/configs/<platform>.json` 的 `rule_variant.fan_table` 字段，便于调整不重新发版。

## 7. 对引擎实现的具体影响

| 规则差异 | 引擎要做的事 |
|---|---|
| **无顺子胡型** | shanten 算法只数刻子 + 对子，搜索树极小，可暴力枚举 |
| 无吃 | 副露区数据结构只有碰、杠两种 |
| 无字牌 | shanten 表只覆盖序数牌（三色版本 27 种 / 单色版本 9 种） |
| 无赖子 | 完全标准枚举，无万能牌处理 |
| 乱将 | 任意对子可做将 |
| 杠 = 一根筋 | 番数 +1，引擎评分时计入期望番数 |

### 7.1 防守逻辑的关键差别（vs 转转麻将）

转转麻将的 [docs/04 决策引擎](04-decision-engine.md) 防守评分用了「现物 / 筋 / 壁」三件套。在株洲碰胡里：

| 概念 | 株洲碰胡是否适用 | 说明 |
|---|---|---|
| 现物 | ✅ 适用 | 别家打过的牌再打 100% 安全 |
| 筋 | ❌ **不适用** | 「筋」依赖两面听（顺子搭子），株洲碰胡无顺子 |
| 壁 | ⚠️ **大部分不适用** | 壁主要阻碍顺子搭子，碰胡里只在阻碍"暗刻形成"上有微弱意义 |
| 单骑/双碰预测 | ✅ **主要防守信号** | 监测对手碰过的牌附近、未弃的对子 |

具体防守模型留 Sprint 7 设计，本文档只锁定方向。

## 8. 不确定/平台变体（必须实测确认）

以下规则在闲逸棋牌对接时**必须实测确认**，逐条写入 `assets/configs/<platform>.json` 的 `rule_variant`：

- [ ] 牌张总数：108（三色）/ 36（单色）/ 其他
- [ ] 起手胡是否启用，有哪些牌型
- [ ] 抢杠胡是否允许；暗杠是否可抢
- [ ] 七对子是否成立
- [ ] 全求人 / 四暗刻 是否作为加番
- [ ] 一炮多响是否允许
- [ ] 流局是否退分
- [ ] 听牌后能否改听（一般禁止）
- [ ] 番数倍率具体值
- [ ] 是否允许海底胡 / 杠上花加番

每条变体在配置里有开关，引擎根据配置切换。

## 9. 引擎单元测试必覆盖的局面

- **典型胡**：3 个明刻 + 1 个暗刻 + 1 对将
- **暗杠后摸到将**：4 副刻子（含 1 杠）+ 听单钓将
- **听单刻**：3 副刻子 + 1 对将 + 1 张孤张，听同张第二个
- **听双碰**：3 副刻子 + 2 对将，听两个对子中任一升级为刻子
- **听单钓将**：4 副刻子 + 1 张孤张，听该张配对
- **全求人**：4 副副露（碰/杠）+ 1 张孤张听将
- **清一色**（三色版本下）：14 张全同色，4 副刻子 + 1 对将
- **四暗刻**：4 个暗刻 + 1 对将（无任何碰/杠）

## 10. 与转转麻将的关系

转转麻将（[docs/06](06-zhuanzhuan-rules.md) 已 deprecated）允许顺子胡型，株洲碰胡只允许刻子胡型。**两者引擎不互通**：

- 转转麻将引擎拿来用 → 会把"4 顺 + 将"判成胡，错
- 株洲碰胡引擎拿来用 → 会把任何带顺子的牌型判成未胡，漏

如果未来 Mayou 要同时支持两种玩法（PRD 未承诺），引擎层必须按 `rule_variant.win_type_set` 切换胡牌型判定。
