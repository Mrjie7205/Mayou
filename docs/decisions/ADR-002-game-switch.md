# ADR-002 · 核心游戏切换：转转麻将 → 株洲碰胡

- **状态**：Accepted
- **日期**：2026-05-12
- **决策者**：Max
- **影响范围**：项目核心游戏、规则文档、引擎选型、所有 Sprint 内容
- **关系**：本 ADR 修订 PRD 初稿对核心游戏的设定，不取代任何旧 ADR

## 背景

Mayou 项目初稿 PRD 把核心游戏设定为转转麻将。Sprint -1 平台选型完成（[ADR-001](ADR-001-platform.md)：红手指 + 闲逸棋牌）后，重新审视三个候选游戏的工程难度，看 MVP 路径是否可以更短：

- 转转麻将（PRD 原方案）
- 株洲碰胡
- 跑得快

核心问题：单人 2 小时/周投入，从零起步，哪个能最快走完 MVP-1 → MVP-2，且不违反 CLAUDE.md 硬约束（特别是「不接神经网络 AI」）？

## 分析

引入一个简单评估框架：

> **总工程难度 = 问题内在复杂度 − 可复用资产**

| 游戏 | 内在复杂度 | 可复用资产 | 总难度 |
|---|---|---|---|
| 转转麻将 | 中（有顺子分支，shanten 搜索需顺子枚举） | 高（python-mahjong 可 fork 砍 60% 工作） | 中 |
| **株洲碰胡** | **极低**（无吃无顺，胡牌型只刻子 + 将） | 几乎为零 | **低** |
| 跑得快 | 极高（搜索博弈、不完全信息、无 shanten 类成熟算法） | 看似中（斗地主 AI 多）实际为零（主流是 RL，违反硬约束 4；启发式开源质量差） | 高 |

### 株洲碰胡为什么内在最简单

核心规则：**胡牌型限定为「全刻子（或杠）+ 1 对将」**，禁止顺子。带来的连锁简化：

- shanten 算法不需要顺子分支搜索，每张牌只可能落在刻子或将里 → 暴力枚举即可，几十行 Python
- 副露区只有碰、杠，状态机不用处理"吃"组
- 听牌型可全枚举（单刻 / 双碰 / 单钓将）
- 蒙特卡洛搜索空间小一个数量级
- 防守端：无两面听 → 「筋」概念不适用，防守模型反而更简单

### 跑得快为什么"参考多 ≠ 容易"

- 主流斗地主开源 AI 几乎都是 RL 训练（DouZero 等），直接违反 CLAUDE.md 硬约束 4
- 启发式开源斗地主质量参差，多停留在演示级
- 跑得快与斗地主的规则差异（角色、牌数、牌型组合、胜负条件）让"化用"工作量约 70% 需要重写
- 出牌评估本质是不完全信息博弈搜索，没有 shanten 类结构化中间状态可复用

### 沉没成本评估

切换不会作废下层资产。CV / 状态机 / UI 层几乎不变：
- 牌识别：仍是 27 种数牌 + 背面
- 状态机：去掉"顺子组识别"，其他事件检测照旧
- UI：完全不变

需要重写的：docs/06（规则文档）+ 引擎层设计细节。整体改动可控。

## 决策

**核心游戏切换为株洲碰胡。**

平台仍按 ADR-001：红手指云手机 + 闲逸棋牌。

## 后果

### 好处

- 引擎层 MVP-2 预计从 4-8 周缩到 1-2 周
- 整体项目周期预计缩短 30%-50%
- 仍走经典 AI 路线，符合所有 CLAUDE.md 硬约束
- 转转麻将文档保留（docs/06 标 deprecated），未来想做转转麻将版本时可复用

### 成本

- 规则文档要新写 docs/07，docs/06 标 deprecated
- PRD / CLAUDE.md / ROADMAP / docs/04 多处涉及游戏名要更新
- 株洲碰胡开源参考极少，引擎核心算法要自写
- 没有现成测试数据集，单元测试用例要手写

### 仍未确认的事项

- 闲逸棋牌「株洲碰胡」的牌数（108 / 84 / 单色 36）、特殊牌型、番数细则需在 Sprint 0 实测时确认，写入 docs/07 §8 与 `assets/configs/<platform>.json` 的 `rule_variant`
- 听牌型完整枚举集合需在 Sprint 5 开始前由 Max 手工列出

## 重新评估触发条件

- 株洲碰胡引擎在欢乐场实战时 >50% 出错（说明规则理解和实现的偏差太大）
- Max 玩腻或转向其他玩法
- 闲逸棋牌下架株洲碰胡
